1. **Установка** — делает пользователь (нужен пароль):
   ```bash
   wsl -d Ubuntu-24.04 -- sudo sh -c "apt update && apt install -y ros-jazzy-ros-gz ros-jazzy-turtlebot3-gazebo"
   ```
2. **Пустой мир с роботом.** Запустить, убедиться, что окно Gazebo **видно** и
   робот в нём есть. Затем вручную дать скорость и проверить, что поза меняется
   (`/odom` или поза из Gazebo). **Остановка:** если за ~1 час Gazebo не рисуется
   или робот не едет — прекратить, записать причину в `ИТОГ.md`, сказать
   пользователю. Дальше решает он (скорее всего, остаётся turtlesim).
3. **Согласовать контроллер с роботом.** Если нужен `TwistStamped` — добавить в
   `controller_node.py` параметр (например `cmd_vel_stamped`, по умолчанию `false`)
   и пробросить его в `demo.launch.py`. По умолчанию должен остаться `Twist`:
   его требует задание и на нём работает turtlesim. Не переименовывать топики и
   параметры, которыми пользуется `demo_turtle.sh`.
4. **Скрипт демонстрации** `C:\Users\kkhod\claude\AIS\project2\step8_demo\demo_gazebo.sh` по
   образцу `demo_turtle.sh`: мир + робот, цепочка, панель, лог на каждый запуск,
   Ctrl+C гасит всё. В пустом мире робот уедет из кадра — продумать: камера,
   следящая за роботом, или стены/сброс позы.
5. **Прогон и проверка фактами:** в логе три действия, поза робота меняется,
   панель в свежей вкладке обновляется.
6. **Запись** — делает пользователь: в кадре одновременно Gazebo, панель, терминал
   контроллера. Проверить запись: кадры извлекаются `opencv` (`cv2.VideoCapture`),

## Грабли, на которые уже наступали

- **PowerShell → `wsl … bash -lc "…"` портит кавычки.** Переменные `$x`, вложенные
  `"`, скобки в `python3 -c` ломаются. Надёжно: писать скрипт в файл, копировать в
  WSL через `tr -d '\r' < '/mnt/c/…/x.sh' > ~/x.sh` и запускать `bash ~/x.sh`.
- **`pkill -f шаблон` убивает собственную оболочку**, если шаблон есть в её
  командной строке (код выхода 9 или 15). Писать шаблон как `'[g]radio_panel'`.
- **Процесс, запущенный в `wsl -- bash -lc "... &"`, умирает вместе с командой.**
  Для долгих процессов — фоновая задача инструмента, а не `&` внутри короткого вызова.
- **Окно WSLg может существовать, но быть не видно:** свёрнуто (координаты −25600)
  или под другим окном. Проверять перечислением окон Windows
  (`EnumWindows` + `GetWindowTextW` с `CharSet = CharSet.Unicode` — без него заголовок
  обрезается до первой буквы и окно «не находится»).
- **Вкладка Gradio, открытая пока сервер лежал, застревает** в переподключении и
  остаётся пустой навсегда. Лечится новой вкладкой.
- **gradio в WSL** стоит в `~/.local` вместе с matplotlib 3.11 (системный 3.6 падал
  на NumPy 2). Не откатывать NumPy на 1.x — сломаются opencv 5 и onnxruntime.
- **В скриптах с `source /opt/ros/jazzy/setup.bash` нельзя `set -u`** — падает на
  `AMENT_TRACE_SETUP_FILES`.
- **Контроллер дописывает лог**, а не перезаписывает — имя лога делать уникальным.
- **`apt install` → 404** значит устаревший индекс: сначала `apt update`.
- `setup.cfg` в пакете (`install_scripts=$base/lib/birdcls`) не удалять — без него
  `ros2 run` не находит узлы.
- Препроцессинг в `classifier_node.py` — масштаб по короткой стороне и центральная
  обрезка (функция `square`). Не заменять на простой `resize`.
