## Топики

| топик | тип | кто → кто |
|---|---|---|
| `/image/compressed` | `sensor_msgs/CompressedImage` | camera_publisher → classifier_node, панель |
| `/model_result` | `std_msgs/String` (JSON) | classifier_node → controller_node, панель |
| `/action` | `std_msgs/String` (JSON) | controller_node → панель |
| **`/cmd_vel`** | **`geometry_msgs/TwistStamped`** | controller_node → `ros_gz_bridge` → gz `cmd_vel` (`gz.msgs.Twist`) → DiffDrive |
| `/odom` | `nav_msgs/Odometry` | Gazebo → `ros_gz_bridge` → ROS (проверка движения) |
| `/clock`, `/tf`, `/joint_states`, `/scan`, `/imu` | стандартные | Gazebo → ROS, в цепочке не используются |

retreat (−0,15 м/с; 0,6 рад/с); ниже уверенности 0,34 — (0; 0).

## Что правилось в коде и почему

1. **`birdcls/controller_node.py`** — параметр `cmd_vel_stamped` (по умолчанию `false`).
   При `true` публикуется `geometry_msgs/TwistStamped` (штамп времени, `frame_id =
   base_footprint`), иначе `Twist`. Причина: мост TurtleBot3 в Jazzy настроен на
   `TwistStamped` (`turtlebot3_burger_bridge.yaml`); на `Twist` робот молча стоит —
   проверено: 6 с по 0,2 м/с, x не изменился. Проверка регрессии: без параметра узел
   публикует `geometry_msgs/msg/Twist`.
2. **`launch/demo.launch.py`** — аргумент `cmd_vel_stamped`, пробрасывается в контроллер.
   Имена прежних аргументов и топиков не менялись; `demo_turtle.sh` работает как был.
3. **Новое:** `step8_demo/demo_gazebo.sh`, `step8_demo/gazebo/tb3_world.launch.py`,
   `step8_demo/gazebo/worlds/empty_local.sdf`.

Пакет пересобран в `~/ros2_ws`, копия в WSL совпадает с исходниками в `project2\ros2_ws`.

## Трудности

1. **Окна WSL приходят в Windows пустыми и прозрачными.** Окно существует, стоит поверх
   всех, значок на панели задач активен, но на экране его нет; в заголовке
   `[WARN:COPY MODE]`. Причина в журнале `/mnt/wslg/weston.log`:
   `rdp_allocate_shared_memory: Failed ... Input/output error` — при старте WSLg не открыл
   общую память и перешёл в режим копирования. Бывает не при каждом старте WSL, в том
   числе когда WSL сам засыпает по простою и просыпается к следующей команде. Лечится
   `wsl --shutdown` и новым запуском; `demo_gazebo.sh` проверяет эту строку и сразу
   говорит, что делать. В том же состоянии невидимо и окно turtlesim.
2. **Штатный мир не запускается без интернета.** `empty_world.world` подключает Ground
   Plane и Sun из Fuel; хранилище `gz-fuel-resources-production.s3.amazonaws.com` из WSL
   недоступно → `Unable to find uri[...Ground Plane]`, сервер выходит. Решение — свой мир.
3. **`TwistStamped` вместо `Twist`** — см. «Что правилось», п. 1.
4. **Нет GPU-отрисовки.** `glxinfo`: `llvmpipe`; D3D12 не поднимается (`X Error BadValue`).
   Gazebo рисует программно; real-time factor 0,8–0,95 для одного мира и 0,24–0,36 с
   цепочкой и панелью (на видео в углу окна 31–36 %). Робот в симуляции едет медленнее
   реального времени — на видео это заметно, на решения контроллера не влияет: он
   работает по стенному времени, 4,9 решения в секунду.
5. **Робот мелкий** при камере по умолчанию — камера следует за ним (`/gui/follow`).
6. **Снимки окна WSLg с Windows**: `PrintWindow` даёт чёрное. Надёжные способы — служба
   Gazebo `/gui/screenshot` или снимок экрана, когда окно наверху.
