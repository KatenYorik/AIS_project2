# Шаг 8. Совмещённая демонстрация

**Задание.** Видео, на котором **одновременно** видны живой вход датчика, робот,
реагирующий в **Gazebo** или в реальности, и **панель Gradio**, обновляющаяся вживую. Не
меньше **трёх различных действий** робота, вызванных выходом модели. В отчёте описать мир
симуляции или реальную установку.

## Что сделано — turtlesim

**Видео записано:**
`C:\Users\kkhod\Videos\Screen Recordings\Screen Recording 2026-09-13 185540.mp4`,
3 мин 23 с, 145 МБ.

В кадре одновременно:

- окно turtlesim с роботом и его траекторией;
- панель Gradio: текущий кадр входа, вероятности, выбранное действие, таблица риска и
  неоднозначности, лента состояний;
- терминал контроллера со строками вида `alert (0.99) → ПОДЪЕХАТЬ  G={…}`.

**Симулятор.** turtlesim — встроенный симулятор ROS 2: плоское поле 11×11 со стенами и робот
с кинематикой дифференциального привода. Он принимает `geometry_msgs/Twist` в
`/turtle1/cmd_vel` — тот же тип сообщения, что и настоящий мобильный робот. Черепаха
появляется в центре поля (5,54; 5,54) и оставляет след. Контроллеру достаточно параметра
`cmd_vel:=/turtle1/cmd_vel`, код не меняется.

**Вход** — видеофайл `DSCN2701.MOV` собственной съёмки, 5 кадров/с по кругу. По номеру он
соответствует проверочному клипу `kormushka2701`: модель его не видела.

**Контроллер** — с измеренной матрицей ошибок (`confusion:=…pretrain_stage2.json`). Только
так появляются все три действия (шаг 6).

## Gazebo — в работе, отдельный чат

Задание называет Gazebo; turtlesim — страховка. Засчитывается ли он, надо спросить у
преподавателя.

Демонстрация в Gazebo ведётся в отдельном чате, чтобы не расходовать контекст основного.
Всё для него — в [`gazebo\CLAUDE.md`](gazebo/CLAUDE.md): задача, что уже работает, план с
точкой остановки, грабли. Итог он запишет в `gazebo\ИТОГ.md`, по нему дописывается
раздел 8 отчёта. Скрипт демонстрации будет `demo_gazebo.sh` в этой папке.

## Файлы

| файл | что делает |
|---|---|
| `demo_turtle.sh` | turtlesim + вся цепочка + панель одной командой; журнал решений на каждый запуск свой; Ctrl+C гасит всё и печатает сводку действий |
| `log_summary.sh` | сводка журнала решений: действия, классы, пары, длины серий, уверенность |
| `arrange_windows.ps1` | ставит окно TurtleSim слева, терминал справа и печатает область для записи |
| `gazebo\` | отдельный чат про Gazebo |

**`demo_turtle.sh`** можно настроить переменными окружения: `CLIP`, `MODEL`, `CONF`,
`PANEL`, `LOG`. По умолчанию — `~/clip.mov`, `~/best.onnx`,
`data/results/pretrain_stage2.json`, панель из `step7_gradio_panel`,
`~/demo_log_<время>.csv`. Перед стартом проверяет, что порт 7860 свободен.

## Как повторить запись

1. Запустить демонстрацию:
   ```bash
   wsl -d Ubuntu-24.04 -- bash /mnt/c/Users/kkhod/claude/AIS/project2/step8_demo/demo_turtle.sh
   ```
2. Когда появится рамка «Идёт демонстрация» — открыть в браузере **новую** вкладку
   `http://127.0.0.1:7860`.
3. Разложить окна так, чтобы были видны черепаха, панель и терминал. Можно командой:
   ```powershell
   powershell -ExecutionPolicy Bypass -File C:\Users\kkhod\claude\AIS\project2\step8_demo\arrange_windows.ps1
   ```
4. `Win+Shift+R`, выделить область, записать минуту-полторы. Ctrl+C в окне демонстрации.
5. Сводка журнала:
   ```bash
   wsl -d Ubuntu-24.04 -- bash /mnt/c/Users/kkhod/claude/AIS/project2/step8_demo/log_summary.sh ~/demo_log_<время>.csv
   ```

## Трудности

- **Окно черепахи «не открывалось».** На деле оно открывалось маленьким (461×478) в левом
  верхнем углу и пряталось под развёрнутым терминалом. Проверка перечислением окон сначала
  ошибочно говорила «окна нет»: без `CharSet.Unicode` заголовок `TurtleSim` читался как `T`.
- **Game Bar пишет одно окно**, а нужны три. Решение — запись области (`Win+Shift+R`).
- **Черепаха упирается в стену.** Сброс: `ros2 service call /reset std_srvs/srv/Empty`.
- **Пустая панель** — вкладка, пережившая перезапуск сервера. Открыть новую.
- **Числа двух прогонов легко перепутать**: 13:22 (без панели) и 18:55 (итоговый). Все числа
  выше — только из `demo_log_185555.csv`.
