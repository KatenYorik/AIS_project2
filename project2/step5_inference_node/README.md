# Шаг 5. Узел вывода

**Задание.** При запуске загрузить модель ONNX в `onnxruntime`, привести вход к нужной
форме и публиковать сообщение с **именем предсказанного класса и уверенностью**.

Узлы лежат в пакете: `project2\ros2_ws\src\birdcls\birdcls\`.

## `classifier_node.py`

- При запуске загружает модель в `onnxruntime` (CPU).
- На каждый кадр из `/image/compressed`: декодирует JPEG, масштабирует по короткой
  стороне до 224, берёт центральный квадрат, BGR → RGB, делит на 255, приводит к
  `NCHW`, выполняет ONNX.
- Если выход не распределение (модель экспортирована без софтмакса), применяет софтмакс
  сам.
- Публикует в `/model_result`:

```json
{"stamp": 1789292410.68, "label": "alert", "confidence": 0.9957,
 "probs": {"alert": 0.9957, "empty": 0.0042, "feeding": 0.0002}, "latency_ms": 13.06}
```

| параметр | по умолчанию | что |
|---|---|---|
| `model` | `best.onnx` | путь к модели |
| `classes` | `alert,empty,feeding` | имена в порядке выхода модели |
| `imgsz` | 224 | сторона входа |

Каждые 50 кадров пишет в журнал медиану задержки.

**Порядок классов** — первое, что проверять при любой правке. У модели он алфавитный, а в
`efe.py` состояния перечислены иначе. Всё сходится, потому что узел отдаёт **имена**
классов, а не индексы.

## `camera_publisher.py`

Веб-камера или видеофайл → `/image/compressed`, JPEG качества 85.

| параметр | по умолчанию | что |
|---|---|---|
| `source` | `0` | номер камеры или путь к файлу |
| `fps` | 5.0 | частота публикации |
| `loop` | true | файл по кругу |
| `width` | 640 | ширина кадра на шине (с сохранением пропорций) |

## Измерено в работающей цепочке

- кадры идут с частотой **5,000 Гц**, период 0,199–0,201 с;
- медиана задержки сети в узле — **8–34 мс** в разных прогонах. Она растёт, когда на той
  же машине работают панель и симулятор.

## Ошибка, найденная при запуске

Сначала узел готовил вход простым `resize` до 224×224 и **сплющивал** кадр 16:9 в
квадрат, а модель учили на центральной обрезке. Сеть получала сжатую по горизонтали
птицу. Численная сверка экспорта такого не ловит: там оба пути получают одинаково
подготовленный квадрат. Исправлено функцией `square` — и здесь, и в панели Gradio.

## Как запустить отдельно

WSL, после сборки пакета (шаг 4):

```bash
ros2 run birdcls camera_publisher --ros-args -p source:=$HOME/clip.mov -p fps:=5.0
ros2 run birdcls classifier_node --ros-args -p model:=$HOME/best.onnx
ros2 topic echo /model_result
```
