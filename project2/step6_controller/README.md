# Шаг 6. Контроллер

**Задание.** Пакет ROS 2, узел подписан на `/model_result` и отображает каждый класс в
командное сообщение (`geometry_msgs/Twist` в `/cmd_vel` для мобильного робота). Все
отображения явные и документированы. **Настраиваемый порог уверенности**, ниже которого
отправляется безопасная команда.

Узел и модель лежат в пакете: `project2\ros2_ws\src\birdcls\birdcls\controller_node.py`
и `efe.py`. Здесь — анализ поведения контроллера.

## Как выбирается действие

Не таблицей «класс → действие», а **минимизацией ожидаемой свободной энергии** по трём
действиям (Парр, Пеццуло, Фристон, гл. 4):

```
G(u) = риск + неоднозначность
риск            = KL( Q(o | u) ‖ P(o) )       насколько ожидаемый исход расходится с желаемым
неоднозначность = E_Q(s | u) H[ A(· | s, u) ]  насколько исход будет неинформативен
```

| элемент | смысл | откуда |
|---|---|---|
| `Q(s)` | вера о сцене | вероятности классификатора |
| `B` | как действие меняет сцену: подъезд пугает, отъезд успокаивает | задано руками |
| `C` | чего робот хочет видеть: кормление +2.0, осмотр +0.3, пусто −1.5 | задано руками — это цель |
| `A` | надёжность наблюдения, **зависит от действия** (вблизи видно лучше) | матрица ошибок модели |

Команда — таблица `MOVE` (шаг 1). Уверенность решения — вес действия в `softmax(−γ·G)`,
γ = 4. В `/action` публикуется разложение `G` на риск и неоднозначность по всем трём
действиям.

## Порог уверенности — в двух видах

- `min_confidence` (0.34): уверенность решения ниже — в `/cmd_vel` уходит (0, 0);
- режим `mode:=threshold` с `threshold` (0.6): обычный порог — класс с вероятностью выше
  порога переводится в действие по таблице, иначе «стоять». Запасной вариант, выполняющий
  требование буквально.

| параметр | по умолчанию |
|---|---|
| `mode` | `efe` (или `threshold`) |
| `threshold`, `min_confidence`, `gamma` | 0.6, 0.34, 4.0 |
| `confusion` | путь к `results\<запуск>.json` — матрица ошибок как `A` |
| `cmd_vel` | `/cmd_vel` (для turtlesim `/turtle1/cmd_vel`) |
| `log` | CSV с потоком решений: `stamp, label, p_feeding, p_alert, p_empty, action, confidence, risk_best, ambiguity_best` |

## Главный результат шага: откуда брать `A`

Прогон контроллера на уверенных входах:

| вход | `A` руками | `A` из итоговой модели | `A` из `frozen_augoff` |
|---|---|---|---|
| уверенно `feeding` | подъехать | подъехать | стоять |
| уверенно `alert` | стоять | **подъехать** | подъехать |
| уверенно `empty` | отъехать | отъехать | **подъехать** |
| неуверенно | стоять | **подъехать** | подъехать |

**Это не ошибка контроллера.** Итоговая модель называет кормление осмотром в 36 случаях из
57 и ни разу не говорит `feeding`. Поэтому `P(наблюдаю alert | сцена feeding) = 0.62`, и
`alert` оказывается лучшим признаком кормления. Подъезд на `alert` — правильный
байесовский вывод из плохого датчика.

Проверено на turtlesim:

| `A` | approach | hold | retreat |
|---|---|---|---|
| руками | **0** | 318 | 129 |
| из матрицы ошибок | 268 | 16 | 95 |

С `A` руками «подъехать» не возникает вовсе. **Поэтому демонстрация идёт с измеренной
`A`** — только так выполняется требование о трёх действиях, и только это честно.

## Свой результат: темп решений — `decision_rate.py`

Птица по разметке меняет состояние **19,7 раза в минуту** (2,7 с в состоянии). Прогон
контроллера по разметке с моделью шума «правильный класс с вероятностью `acc`, остальное
поровну» предсказывал: выше точности 0,75 темп совпадает с птицей, ниже 0,7 контроллер
**глохнет** (при 0,5 — 3,3 смены в минуту).

На записанном прогоне при accuracy модели 0,51 — **48,4 смены в минуту**. Предсказание не
подтвердилось: настоящая сеть ошибается **уверенно** (`alert` 0,98 при кормлении), а не
размыто, и контроллер следует за каждым скачком. Вывод: шум надо моделировать матрицей
ошибок и распределением уверенности, а не одним числом точности. Для этой модели нужно
сглаживание во времени.

## `estimate_B.py` — попытка измерить `B`

время кормления **37 с** у них против **1,7 с** у нас. Разница — не биология, а

чужую `B` нельзя. Итог — в `data\B_data.json`, разбор — `СМЫСЛ_ПРОЕКТА2.ru.md`.

## Ошибка, которую уже совершали

Контроллер вырождался в «всегда отъезжать», пока `A` не зависела от действия. Если
неоднозначность одинакова для всех действий, она не влияет на выбор, и подъезжать
незачем. Правило: одно и то же действие всегда — искать член, одинаковый для всех
действий.
