## Два окружения, и это не усложнение, а экономия

Работа делится на две части, и им нужны разные вещи:

| | где | что нужно | зачем |
|---|---|---|---|
| **Проект 1** — обучение, метрики, демо с камерой | обычный Windows | питон + пакеты | это всё ставится за десять минут |
| **Проект 2** — узлы ROS 2 | WSL (Linux внутри Windows) | ROS 2 | под Windows напрямую ROS 2 ставится плохо |

**Почему так, а не всё в одном месте.** ROS 2 родом из Linux; под Windows он есть, но
установка капризная. Через WSL — надёжнее и быстрее.

Но есть ловушка, о которой стоит знать заранее: **веб-камера в WSL не видна.** Пробрасывать
USB-устройства туда можно, но это отдельная возня на час. Поэтому:

- **демо с веб-камерой** (требование Проекта 1) снимается на обычном Windows, панелью
  `gradio_panel.py --mode local` — никакого ROS для этого не нужно;
- **демо цепочки ROS 2** (требование Проекта 2) снимается в WSL, но источником берётся
  **видеофайл**, а не камера: `-p source:=clip.mp4`.

Так оба требования закрываются, а час на проброс USB не тратится.

## Шаг 1. Windows: пакеты для Проекта 1 — 10 минут

Проверить, что уже есть:

```powershell
cd C:\Users\kkhod\claude\AIS\common
python check_env.py
```

Он напечатает таблицу: что стоит, каких версий и чего не хватает. Потом:

```powershell
powershell -ExecutionPolicy Bypass -File setup_windows.ps1
```

Что ставится и зачем:

| пакет | зачем |
|---|---|
| `ultralytics` | обучение классификатора. Тянет за собой `torch` — это ~2 ГБ и самая долгая часть |
| `onnx`, `onnxruntime` | экспорт модели и её быстрый прогон без питоновской обвязки |
| `clearml` | версии датасета и журнал запусков |
| `gradio` | панель для демо |
| `opencv-python`, `pillow` | чтение видео и кадров |

`--ExecutionPolicy Bypass` нужен потому, что Windows по умолчанию не запускает скачанные
скрипты. Это разрешение только на один запуск, настройки системы не меняются.

После установки — ещё раз `python check_env.py`. Если внизу написано «ВСЁ НА МЕСТЕ для
Проекта 1» — можно обучать.

Один раз завести ключи ClearML:

```powershell
clearml-init
```

Он попросит вставить строку с `app.clear.ml` (Settings → Workspace → Create new
credentials). Минута.

## Шаг 2. Проверить, есть ли ROS 2 — 1 минута

```powershell
wsl --list --verbose
```

А внутри WSL:

```bash
echo $ROS_DISTRO          # напечатает jazzy / humble — значит ROS 2 стоит
ros2 pkg list | head -3   # если пошёл список пакетов, всё в порядке
```

**У команды `ros2` нет флага `--version`** — если написать `ros2 --version`, она ответит
`unrecognized arguments`. Это НЕ значит, что ROS 2 сломан: наоборот, раз команда
разобрала аргументы и пожаловалась, она установлена и работает. Версия узнаётся
переменной `ROS_DISTRO`.

**Если `echo $ROS_DISTRO` что-то напечатал** — ROS 2 стоит, переходи к сборке пакета,
установка не нужна.

**Если нет** — читай дальше. И начни это сегодня, а не в день сдачи: тут единственное
место во всей работе, где может уйти два часа не по твоей вине.

## Шаг 3. WSL и ROS 2 — 1,5–2 часа, из них почти всё ожидание

### 3.1. Поставить WSL с Ubuntu 24.04 (15 минут + перезагрузка)

В PowerShell **от имени администратора**:

```powershell
wsl --install -d Ubuntu-24.04
```

Компьютер попросит перезагрузиться. После перезагрузки откроется окно Ubuntu, оно
спросит имя пользователя и пароль — придумай любые, они нужны только внутри Linux.

Если `wsl --install` ругается, что WSL уже есть, но списка нет:

```powershell
wsl --update
wsl --install -d Ubuntu-24.04
```

### 3.2. Поставить ROS 2 Jazzy (30–60 минут, в основном загрузка)

Всё дальше — **внутри окна Ubuntu**, не в PowerShell.

```bash
sudo apt update && sudo apt install -y software-properties-common curl
sudo add-apt-repository universe -y

sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key \
     -o /usr/share/keyrings/ros-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] \
http://packages.ros.org/ros2/ubuntu $(. /etc/os-release && echo $UBUNTU_CODENAME) main" \
  | sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null

sudo apt update
sudo apt install -y ros-jazzy-ros-base python3-colcon-common-extensions
```

Чтобы не набирать `source` каждый раз:

```bash
echo "source /opt/ros/jazzy/setup.bash" >> ~/.bashrc
source ~/.bashrc
echo $ROS_DISTRO
```

### 3.3. Питоновские пакеты внутри WSL (10 минут)

Узлы работают внутри Linux, значит и пакеты им нужны там же. Внутри Ubuntu:

```bash
sudo apt install -y python3-pip python3-venv
pip install --break-system-packages onnxruntime opencv-python-headless numpy
```

`opencv-python-headless`, а не обычный: внутри WSL нет графической оболочки, а
безголовая версия легче и ставится без хлопот. Узлам показывать окна не надо.

`--break-system-packages` — Ubuntu 24.04 защищает системный питон от pip. Флаг говорит
«я знаю, что делаю». Для одноразовой учебной установки это нормально.

### 3.4. Собрать наш пакет (5 минут)

Твои файлы видны из WSL по пути `/mnt/c/...`:

```bash
mkdir -p ~/ros2_ws/src
cp -r /mnt/c/Users/kkhod/claude/AIS/project2/ros2_ws/src/birdcls ~/ros2_ws/src/
cd ~/ros2_ws
colcon build --packages-select birdcls
source install/setup.bash
ros2 pkg list | grep birdcls
```

Копировать, а не собирать прямо на диске C, стоит по скучной причине: сборка на
примонтированном диске идёт втрое медленнее.

### 3.5. Проверить, что цепочка жива (10 минут)

```bash
cp /mnt/c/Users/kkhod/claude/AIS/data/runs/classify/pretrain_stage2/weights/best.onnx ~/
ros2 run birdcls camera_publisher --ros-args -p source:=$HOME/clip.mp4 -p fps:=5.0
# во втором окне:
ros2 run birdcls classifier_node --ros-args -p model:=$HOME/best.onnx
# в третьем:
ros2 topic echo /model_result
```

Если в третьем окне побежал JSON — Проект 2 работает. Дальше по `PROJECT2.ru.md`.

## Если что-то пошло не так

**`python` не находится.** Питон стоит, но не прописан в PATH. Проще всего переустановить
с python.org и отметить галочку «Add python.exe to PATH».

**pip ругается на права.** Открой PowerShell от имени администратора либо добавь `--user`
к команде установки.

**`wsl --install` требует включить виртуализацию.** Это делается в BIOS (пункт называется
Intel VT-x или AMD-V). Перезагрузка, F2 или Del при старте. Если в BIOS лезть не хочется —
скажи, обсудим вариант с нативной установкой ROS 2 под Windows, он хуже, но существует.

**Обучение идёт слишком долго.** Проверь вывод `check_env.py`: если видеокарты нет, это
нормально. Можно перенести обучение в бесплатный Colab — там минут пять, и `train.py`
работает там без изменений.

**Не хватает места на диске.** `torch` плюс ROS 2 — это около 8 ГБ. Если тесно, начни с
Windows-части: Проект 1 закрывается без ROS вообще.
